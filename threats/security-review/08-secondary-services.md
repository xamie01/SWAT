## A. Boundaries and execution map

**LP HTTP and storage.** Fastify binds `0.0.0.0`, default port 3010. Production refuses missing `API_KEY`; nonproduction warns that sessions remain available, but actually registers the entire auth hook only when that key exists (`apps/lp/src/index.ts:52-62,298-300,408-409`). Registered authentication resolves an active session first, requires matching CSRF cookie/header for writes, and otherwise accepts a timing-safe hashed service key. Service principals have no tenant and cannot use `requireUser`; invalid sessions do not fall through to service authentication (`apps/lp/src/auth.ts:39-47,63-102`). Position lookup and state changes are tenant-scoped; transitions lock the owned row and journal it atomically (`packages/db/src/lp-positions.ts:219-224,328-375`). This is not a finding of unauthenticated global position access.

### Numbered remediation and neighboring-path compatibility

1. **SEC-01/02: correct HTTP policy without removing tenancy.** Reject origins outside exact configured scheme/host/port; remove both the `:3000` suffix acceptance and final unconditional allow. SameSite is site-level, not origin-level; Lax does not protect against every same-site origin. No assertion of unrelated-site session theft is supported. Always register the session branch, making the service-key hash optional while preserving invalid-session refusal and constant-time matching. Keep the health exemption and double-submit CSRF; do not make scoped routes accept tenantless service keys (`apps/lp/src/auth.ts:63-102`).

2. **SEC-03: make subscriber onboarding an explicit bounded privilege.** Allow requesting a master, not modifying established global registry metadata. Preserve service-only add/delete. Authenticate and fully validate before registry effects, apply tenant/global quotas, and make subscription/onboarding atomic or recoverable. Budget validation currently uses coercion and `<=0` without finite checks in both route and DB; venue has a SQL allowlist, so do not claim arbitrary venue persistence (`apps/lp/src/routes.ts:477-505`; `packages/db/src/lp-copy-trading.ts:103-136`; `packages/db/sql/069_lp_copy_trading.sql:9-17`). Explicitly reject nonnumeric/nonfinite budgets in code and SQL; actual PostgreSQL special-NUMERIC acceptance was not tested. Registry mutation already occurs before any subscription SQL constraint failure.

3. **SEC-04: identify units and reserve the decision.** Store exact raw quantity, decimals, asset, valuation timestamp/source and mode independently. Sum trusted USD commitments including building/pending exposure; retain unknown commitments. Lock a tenant budget/reservation ledger through check-and-insert, not merely individual position transitions. Preserve the pure evaluator's finite checks; its intentional first-deposit exception is not itself a NaN bypass (`apps/lp/src/guardrails/exposure-cap.ts:37-65`). Migration must not relabel historical raw amounts as USD without evidence.

4. **SEC-05: distinguish plans from execution.** Before creating a live build, require certified runtime and an actual per-user address/grant rather than the process-global `LP_SERVICE_USER_ADDRESS` (`apps/lp/src/index.ts:307`; `apps/lp/src/builder/build-position.ts:208-224`). Current plan-only ports do not sign, so this is a future ownership boundary, not present user-fund theft. Journal paper rebalance completion/failure, compensate builder failures after insertion, and implement explicit canceled/planned states. DB-only LP close must remain paper/archive-only until receipt-based withdrawal exists (`apps/lp/src/routes.ts:371-400`). Preserve locked transitions. The separate copy handler must never report live `executed` without submission/evidence: it currently only updates DB, and paper also creates no simulated position (`apps/lp/src/copy/copy-worker.ts:62-73`). Do not wire that dormant worker before tenant/subscription revalidation and unique event identity; SQL executions have no event uniqueness (`packages/db/sql/069_lp_copy_trading.sql:28-50`).

5. **SEC-06/07: keep perps behind a certification boundary.** Reject unknown/inactive instruments; enforce finite positive exact price, quantity, leverage and notional, configured precision, limit/slippage and freshness. Preserve legitimate zero withdrawable; malformed maintenance/initial margin must refuse, not become zero or NaN. Bind session identity to the tenant and active grant before effects. Transmit stable client identity under the SDK contract and persist submitting/unknown state before `placeOrder`. Reconcile authoritative net positions rather than inserting a new position for each partial fill; the function named upsert actually INSERTs (`packages/db/src/polymarket-perps.ts:177-218`). Do not publish the pretrade portfolio as posttrade state or approximate liquidation as authoritative (`apps/trade-executor/src/polymarket-perps.ts:219-251`). For close, keep SQL archive distinct; real close requires reduce-only venue order plus evidence. Returning affected rows fixes the false 404 but does not implement a venue close.

6. **SEC-08: decouple notifications from execution state.** Update only notification metadata; never downgrade executing/executed signals. Use durable notification intent, token-owned lease renewal and compare-and-delete; lock denial should delay rather than complete the job. Bound request and server retry delay. Delivery followed by DB failure remains an ambiguous external effect, not exactly-once. Operational payloads are escaped, but signal strings are only length-checked and several are inserted raw into HTML/links (`apps/alert-service/src/alert-payload.ts:96-113,246-269`; `apps/alert-service/src/index.ts:253-265,293-294,355-369`). Validate IDs/addresses, escape text and encode URL components. Telegram rendering impact needs isolated tests; no browser XSS claim. Replace universal displayed 15% with resolved venue/user policy, since it is presentation, not proof of actual execution (`apps/alert-service/src/index.ts:318-342`).

7. **SEC-09/10: preserve recovery and local isolation.** Discovery should write wallet plus outbox transactionally and acknowledge enqueue independently; existing deterministic backfill IDs remain useful. Process overlap guards are not cross-replica ownership (`apps/discovery/src/runner.ts:35,99-114`). Python should resolve paths beneath an explicit permitted root, reject traversal/absolute address components, use canonical encoded partitions, and authenticate artifact provenance before deserialization. Preserve `yaml.safe_load` and parameterized DuckDB filters (`pattern-ml/src/pattern_ml/config.py:197`; `pattern-ml/src/pattern_ml/storage.py:236-255`). Require explicit opt-in to repo credential fallback. Nonpositive rate limits disable pacing and HTTP honors unbounded numeric Retry-After; validate bounded configuration (`pattern-ml/src/pattern_ml/sources/base.py:36-43,110-115`).

## C. Invariants and isolated local-test descriptions

No tests were run. Proposed tests use fake Redis/SQL/SDK/HTTP ports, fixed clocks and temporary directories, never entrypoint imports, real `.env`, credential artifacts or endpoints.

- Exact-origin matrix includes unlisted same-site subdomain, arbitrary port3000 and unrelated site; session-only configuration still authenticates, writes require CSRF and service keys cannot impersonate tenants (SEC-01/02).
- Failed subscriptions cause no shared registry mutation; resubscription cannot change service cadence/label; malformed budgets and unsupported venues fail before side effects (SEC-03).
- Two assets with different USD prices and simultaneous reservations preserve concentration; paper/live/building are separated; quantities around `2^53` remain exact rather than trusting SQL NUMERIC after Number conversion (SEC-04; `packages/db/src/lp-copy-trading.ts:69-95`).
- Unsupported live build/copy refuses without success records; paper rebalance terminates; worker-before-route-transition races remain recoverable (SEC-05).
- Perps zero withdrawable, malformed margins, negative/nonfinite quantity and excessive leverage refuse; lost POST response remains unknown; close cannot hide open venue exposure or return 404 after a committed successful archive (SEC-06/07).
- Fake Telegram delay exceeds60 seconds, send succeeds but SQL fails, and execution completes before alert persistence: no lease theft, silent lost retry or state regression (SEC-08).
- Queue failure after wallet insertion is retried from durable outbox; malicious local path/artifact provenance is rejected without using exploit pickle content (SEC-09/10).

Timing evidence is configured cadence, not measured speed: LP cron is minute-scale; discovery is daily plus pub/sub; alert ingestion/pUSD checks default60,000 ms with10,000–900,000 clamps (`apps/alert-service/src/index.ts:82-86,118-122`). Telegram lacks an application timeout, so no universal alert-delivery ceiling exists. Python HTTP default30 seconds, up to five attempts, does not bound total paging (`pattern-ml/src/pattern_ml/sources/base.py:76-88,100-115`). No percentile/SLA claim is supported.
