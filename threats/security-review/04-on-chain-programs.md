### Important mitigations and limits

**`min_out == 0` is rejected**, both in handler and helper; do not report it as accepted (/home/xahmie/Documents/SWAT/programs/wake-vault/src/lib.rs:251–252,575–580). `max_in` is caller-selected but genuinely bounds **net spend** with checked subtraction; output gain is also checked and must be positive (/home/xahmie/Documents/SWAT/programs/wake-vault/src/lib.rs:568–580). These checks do not establish owner-consented price/mint/cumulative policy (/home/xahmie/Documents/SWAT/programs/wake-vault/src/lib.rs:237–239,506–515). Token authority, disjoint accounts, writable output presence, vault-native preservation, and additional writable **legacy** vault-token rejection are real restrictions (/home/xahmie/Documents/SWAT/programs/wake-vault/src/lib.rs:254–288,324–329,471–486). No arbitrary target CPI or owner-signature bypass was demonstrated.

CPI account metas intentionally make **only vault** a signer, suppressing other incoming signers; owner/executor signatures are not automatically forwarded (/home/xahmie/Documents/SWAT/programs/wake-vault/src/lib.rs:299–315). That limits signer propagation but can break Jupiter routes needing another signer; preserve least privilege, do not “fix” with unconditional `a.is_signer`. Raw Jupiter instruction selector/semantics are not decoded, and token authority/delegate/close-authority changes are not compared after CPI—whether any permitted Jupiter path can exploit those omissions **needs external source or offline fixture verification**, not a confirmed persistent-approval drain (/home/xahmie/Documents/SWAT/programs/wake-vault/src/lib.rs:239,299–329).

Legacy named Token accounts are not Token2022-compatible merely because that ecosystem shares similar base data (/home/xahmie/Documents/SWAT/programs/wake-vault/src/lib.rs:25,425–433,475–486). Blanket “Token2022 accepted” or “extra Token2022 definitely drainable” claims would be unsupported. Tip fields are stored/updated but not consumed by any reviewed instruction; there is no implemented `pay_jito_tip` handler in /home/xahmie/Documents/SWAT/programs/wake-vault/src/lib.rs:41–333. The older skeleton's tip path is explicitly design-only and returns success without doing transfer (/home/xahmie/Documents/SWAT/docs/dg-8/wake-vault-skeleton.rs:5–12,137–157); it is not deployed-program evidence.
