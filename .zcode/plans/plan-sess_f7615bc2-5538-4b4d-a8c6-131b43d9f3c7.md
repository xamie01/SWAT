## Phase 4 completion map

### Current position

The branch has most of the pure decision logic and several production wirings, but the remaining work falls into three different classes:

- **Near-term code path:** finish lot-aware accounting and lifecycle exits, then prove multi-user paper fan-out end to end.
- **Production hardening:** wire and verify the remaining venue, capacity, observability, and monitoring controls.
- **External launch gates:** legal approval, custody/delegation infrastructure, provider decisions, real-chain configuration, and withdrawal controls. These cannot be closed by more TypeScript alone.

The migration/profile boundary is now in place. Core work must continue against clean `*_integration` databases with `SWAT_DB_PROFILE=core`; LP remains opt-in through `SWAT_DB_PROFILE=lp` and stays out of the core implementation.

## Batch 1: Finish S4-M3 lot-aware lifecycle

**Goal:** make every open tenant position attributable to a master lot and closeable through every exit path.

1. **Lot-scoped P&L and stop-loss snapshots**
   - Refactor `packages/db/src/pnl-queries.ts` to derive open snapshots from `copy_position_master_lots` / reductions, preserving the operator aggregate path for legacy rows.
   - Emit one snapshot per open `(user, master, signal, token)` lot scope with `positionKey`; preserve signal-level P&L rollup by summing disjoint lot results.
   - Keep unknown, oversold, mixed-token, and missing-price states fail-closed.
   - Thread `positionKey` into scorer claims, job IDs, and releases while retaining the exact legacy operator behavior.
   - Add tests for two masters on one signal, two lots for one master, FIFO reductions, winding-down users, and independent stop-loss claims.

2. **Manual exit and redemption allocation**
   - Extend the existing Polymarket three-entrant race in `packages/db/src/polymarket-exit-queries.ts` / `apps/trade-executor/src/polymarket-exit-race.ts` to carry lot identity and exact quantity.
   - Allocate manual sells and mirrored sells through the master-lot allocator; redemption must preserve outcome-token identity and allocate proceeds to the matching open lots.
   - Add a chain-generic position-exit claim if manual Solana/Robinhood exits still lack a durable single-shot claim; do not reuse stop-loss claims because their schema is stop-loss-specific.
   - Verify the race remains one winner for mirrored sell, resolution redemption, and manual exit, including concurrent/replay cases.

3. **Close-all consumer and subscription transitions**
   - Add a consumer for `close_all_requested_at` that enumerates exact open lots, enqueues exact-quantity sells, and records idempotent exit claims.
   - Transition `winding_down -> ended` only after no open lots remain; do not end merely because enqueue succeeded.
   - Redirect the API unsubscribe route from hard delete to `beginWindDown` or direct `ended` only when no open positions exist.
   - Change `pauseUnsubscribedWallets` to use `state <> 'ended'` and retain sell eligibility for winding-down rows.
   - Add integration coverage for unsubscribe, close-all replay, final close, and re-subscribe/member-slot behavior.

**Batch gate:** clean core migration replay, lifecycle integration, lot allocator tests, P&L/stop-loss tests, exit-race tests, and explicit integration typecheck all pass.

## Batch 2: Prove the paper fan-out path end to end

**Goal:** turn the existing pure fan-out work into a durable multi-user execution path.

1. **Wire source-signal fan-out fully**
   - Confirm `processSourceTradeSignals` calls candidate enumeration, `planFanout`, capacity resolution, and `enqueueFanoutTradeJobs` exactly once per source signal.
   - Ensure enumeration failure falls back only to the legacy operator job and never accidentally admits users.
   - Ensure `source_dispatched_at` is marked only after all required enqueue work succeeds, with stable per-user job IDs and durable tenant uniqueness guards.

2. **Complete per-user sizing and risk threading**
   - Pass the user principal through sizing, risk policy lookup, breaker keys, rolling exposure, daily exposure, paper bankroll, slippage, and execution settings.
   - Fix the known `FanoutVerdict.downgraded` / requested-mode propagation gap so platform clamping is observable and cannot re-widen downstream.
   - Decide and implement the per-user paper bankroll representation rather than silently sharing the operator bankroll.
   - Keep `RECONCILIATION_ACCOUNT='operator'` separate from risk-policy account keys.

3. **Capacity and ledger verification**
   - Run migration `053` on a clean database and exercise one admitted cohort plus one rejected cohort.
   - Verify the capacity ledger writer is idempotent under evidence replay and that Polygon uses the real Redis book feed while AMM chains use their declared approximate liquidity basis.
   - Confirm capacity skips are uniform and expose only the generic user message; retain detailed internal reason codes.

4. **End-to-end tenant isolation test**
   - Drive two paper users through the same source signal and token.
   - Assert separate `trades`, `copy_executions`, `copy_positions`, lots, P&L, stop-loss claims, job IDs, exposure, and breaker state.
   - Assert legacy operator rows still use null user identity and old job/release compatibility.

**Batch gate:** a clean Docker Postgres/Redis run demonstrates two users copying one signal with disjoint quantities/cost basis, stable retry idempotency, and no cross-user claim or cap interference.

## Batch 5: Custody, authority, and withdrawal launch gates

These are Phase 4 work but not prerequisites for proving paper fan-out. Track them separately so they do not contaminate the core loop:

1. **Authority and EVM:** pin EntryPoint, finish on-chain argument-scoped enforcement, verify the 4663 account/delegate path against a real bundler, and close the remaining Permit2/router configuration.
2. **Solana delegation:** evaluate or implement the audited destination-constrained delegation program; this is the long pole and should not be hidden behind application abstractions.
3. **Polymarket authority:** implement the selected fork-b signer/grant flow, seal credentials, and ensure signing material never leaves trade-executor.
4. **Grant lifecycle:** persist expiry/revocation, warn before expiry, surface lapsed grants as a distinct skip reason, and add re-consent.
5. **Paymaster/relay:** finish the Rialto gasless pricing/quotas decision first; only then build per-user and global sponsored-operation caps if self-paymaster remains selected.
6. **Per-user SOL reserve:** enforce the live USD 10 equivalent gate before each Solana trade with explicit funded/underfunded/price-unknown outcomes.
7. **Withdrawal anti-theft core:** verified email, linked-wallet verification and cooling-off, Resend delivery semantics, signed transfer only to an eligible wallet, daily cap, and adversarial tests.
8. **Legal and geo controls:** counsel/ToS/risk disclosures, Cloudflare geo-block, consent-time Polymarket eligibility with staleness enforcement. These remain external launch gates even after code is complete.

**Batch gate:** no custody launch until the checklist's paper fan-out, withdrawal adversarial suite, key/log/API scan, Vault Transit staging migration, and legal/geo approvals are all green.

## Recommended execution order

1. Batch 1: lot-aware P&L, exits, close-all, unsubscribe.
2. Batch 2: clean-database two-user paper fan-out and capacity verification.
3. Batch 3: Polymarket/Jupiter/Permit2/LP venue gaps in parallel slices.
4. Batch 4: observability, detector coverage, monitors, and CI integration typecheck.
5. Batch 5: custody, withdrawal, provider, and legal gates.

This order preserves the existing safety decisions: no destructive LP cleanup, no fabricated liquidity/prices, no bypass of the three-way Polymarket exit race, no widening of user settings through platform defaults, and no live custody claim before the external controls exist.
